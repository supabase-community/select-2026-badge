# badgecard -- the badge editor and the worn badge itself: name, skin, stickers, effect

At rest it draws the wearer's badge with no chrome at all: artwork, stickers, name, and a whole-surface effect filter. Any key opens a six-row menu that edits all of it, and `SAVE TO HOME` bakes the finished card into a launcher wallpaper film. It is the only writer of the badge state; `poster` and the launcher are read-only consumers of the same files. It arrives in four staged paints (dark field, name, artwork, marks), each wrapped, so a failure leaves the last good stage on the panel instead of a crash modal.

**Controls.** Resting badge: any of A/B/C/UP/DOWN opens the menu and does nothing else. Menu: UP/DOWN scroll (auto-repeat), A back to the badge, B open the row, C clear (on the `SAVE TO HOME` row only). Inside a row A is always back and B is always apply; `STICKERS` adds C to delete and uses A/C/UP/DOWN to nudge a placement. On the delete-a-badge confirm, B is deliberately inert: B may not destroy anything. HOME leaves to the launcher.

**Non-obvious.** HIRES 320x240, unconditionally, and `tests/test_card_resolution.py` walks the package AST and fails if any module names a panel mode at all -- everything downstream reads the resolution off the surface it was handed. Up to five badges live in `/state/badgecard.json`; `/state/wallpaper.pgw` is the baked launcher film and `/state/backdrop.bdr` the artwork cache this app is the sole writer of. Every commit is written synchronously at the press that made it, so `on_exit` has nothing to flush. The catalogue is 106 entries (88 procedural skins plus 18 glyph decks) and exactly one of `skins.py` (666 KB) or `glyphskin.py` (41 KB) is parsed per boot.

**One note about `skins.py` specifically**, because it is the largest file here and its `_SUPA_CACHE` looks like a leak: it holds one entry, keyed on the canvas geometry, and it is the largest single performance win in the catalogue. Built per frame, that skin's `animate` measured 252 ms on device; keyed and held it measures 11.88 ms, which is 21.2x and the difference between twenty panel updates and one 11.43 ms quantum. Its byte size is also captioned in 37 places across the repository by a CI gate, so it is a file to change deliberately rather than in passing.
